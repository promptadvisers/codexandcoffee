# Choosing a home for a change

- The next request: a requirement or detail that applies to this task only
- A skill: a repeatable way to perform the same kind of work
- AGENTS.md: a stable, explicitly supported convention across this project
- Tool or environment: missing access or a broken capability that prose cannot fix

Read the relevant existing file before choosing exact wording. Keep the useful parts of current guidance. Write an observable instruction: "Before finalizing, compare each decision with its source; keep proposals and conditions visible" is stronger than "Be more careful."

Do not put a particular customer's name, a one-off date, a temporary budget, or an uncertain cause into permanent guidance. Do not create a rule simply to fill every category. If the evidence supports one change, make one change.

For a skill change, write a fresh task that would expose the old failure without using the same names, dates or amounts. Also use a nearby ordinary request that should not activate the retrospective. Keep the source case separate from the fresh test.

For a project convention, verify its wording reflects an explicit lasting preference rather than extrapolating from one correction. Instructions do not grant tools, permissions or access.
